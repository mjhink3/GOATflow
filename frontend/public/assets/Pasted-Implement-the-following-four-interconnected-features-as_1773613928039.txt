PART 3 — DIFFICULTY MULTIPLIER SYSTEM
═══════════════════════════════════════════

Implement an adaptive Hay multiplier 
based on each user's personal 
completion history.

CATEGORY DETECTION:
When a Track is generated by the 
Churn Engine, GPT-4o should assign 
it one of these categories as a 
hidden tag (not shown to user):

communication / administrative / 
creative / financial / personal / 
health / technical / planning / 
operational / other

Store the category tag with each Track.

DIFFICULTY SCORE CALCULATION:
After a user has completed 20+ Tracks 
(minimum data threshold) calculate 
a Difficulty Score per category:

Category Difficulty Score = 
  Average days to complete in category
  ÷ Overall average days to complete
  (floor at 0.5, ceiling at 5.0)

Store scores in localStorage as:
'goatflow_difficulty_scores': {
  communication: 2.4,
  administrative: 1.1,
  personal: 3.8,
  ...
}

Recalculate after every 5 new 
completions in any category.

HAY MULTIPLIER APPLICATION:
When a Track is completed apply 
the category difficulty multiplier 
to the base Hay award:

Base Hay × Difficulty Score = Final Hay

Examples:
Standard Track base 10 Hay 
  × 3.8 difficulty = 38 Hay
Summit Call base 50 Hay 
  × 2.4 difficulty = 120 Hay

Show the multiplier on the 
completion animation:
"🌾 +38 Hay (3.8× difficulty)"
in gold, DM Sans 700, 16px
The multiplier number displayed 
prominently so users understand 
why they earned more on some Tracks

Before 20 completions (insufficient data):
Use default multiplier of 1.0
Show "🌾 +10 Hay" as normal

"This user consistently overestimates

[X]% based on historical data."

underestimation (always takes longer):

"This user consistently underestimates

[X]% based on historical data."

Generate a GPT-4o summary using
